옵시디언으로 LLM 위키 만들기

이 저장소의 설명서를 옵시디언(Obsidian)에 모아 두고, 옵시디언 안에서 LLM에게 "이 설명서 기준으로 답해 줘"라고 묻는 방법입니다.

작성 2026-10-07 플러그인 메뉴 이름은 버전에 따라 바뀔 수 있음 · 설치 화면 안내 우선

결론

목적별로 권하는 방법입니다.

목적권하는 방법
노트 보관과 연결이 저장소(repo) 폴더를 그대로 옵시디언 볼트로 연다. 설명서가 코드와 같은 곳에 있어 한쪽만 고쳐지는 일이 줄어든다
PC·폰 동기화Obsidian Git 플러그인으로 GitHub와 동기화 (폰은 느리고 제약이 있음, 3장)
설명서에 질문옵시디언 LLM 플러그인(예: Copilot for Obsidian, Smart Connections) + API 키
설정 없이 바로 질문지금처럼 이 저장소를 연 Claude Code 세션에 묻는다. 코드와 설명서를 둘 다 읽고 답한다
비용옵시디언 LLM 플러그인은 별도 API 키(사용량 과금)가 필요합니다. Claude 구독과는 별개입니다. 설정이 부담되면 마지막 줄의 방법이 가장 간단합니다.

1볼트 만들기

  1. 1옵시디언 설치obsidian.md에서 PC용을 받습니다.
  2. 2저장소 내려받기PC 터미널에서 git clone https://github.com/Macadamia77/RP-Sales_Num_1-fishing_rod.git
  3. 3볼트로 열기옵시디언 시작 화면 → Open folder as vault → 내려받은 폴더 선택
  4. 먼저.gitignore에 두 줄 추가 후 커밋.obsidian/와 *.csv. 이유는 4장.
설명서 폴더만 볼트로 열어도 됨저장소 전체가 부담되면 설명서/ 폴더만 볼트로 열 수 있습니다. 다만 그러면 LLM이 코드(pipeline/, legacy/)는 읽지 못합니다.

2LLM이 읽기 좋은 노트로 정리하기

HTML은 노트로 열리지 않는다 · 읽힐 파일

옵시디언은 마크다운(.md)을 노트로 다루고, LLM 플러그인도 보통 .md만 색인합니다. HTML 설명서는 사람이 브라우저로 보는 용도로 두고, LLM에게는 AI용 md 파일을 읽힙니다.

파일LLM 위키에서의 역할
설명서/수집기_상세_설명서_AI용.md데이터 흐름 Q&A, 단계별 요청·응답, 실행 추적
설명서/수집기_로직_설명서_AI용.md판정 규칙 전체 (순위, 단어 목록, 이름 비교)
docs/코드구조_설명서_AI용.md파일 지도와 실행 흐름
검수보고서.md기존 코드 문제와 위험
README.md실행 방법
설명서/옵시디언_LLM위키_가이드.md이 가이드의 md 판
중복 파일 정리설명서/와 docs/에 같은 이름의 코드구조_설명서_AI용.md가 두 개 있습니다. LLM이 같은 내용을 두 번 읽으면 답이 흔들릴 수 있으니 하나만 남기거나, 플러그인 설정에서 한쪽 폴더를 색인 제외로 두세요.

권하는 폴더 구조 (새로 쓸 노트)

위키/
  00_목차.md      ← 모든 노트로 가는 링크 모음. LLM에게 "목차부터 보라"고 할 때 씀
  용어/            ← 한 용어 한 노트: 주소 묶음, 장소 풀, 이름 대상, 번호 대상, 건물 내 점포 …
  과정/            ← P1~P9 한 과정 한 노트
  결정/            ← "왜 이렇게 했나" 기록 (예: 부동산 DB는 공공데이터로)
  질문/            ← 자주 묻는 질문과 답 (대화에서 나온 Q&A를 옮김)

노트 쓰는 규칙

LLM 플러그인은 노트를 조각내서 질문과 가까운 조각만 읽습니다. 그래서 노트 한 조각만 봐도 뜻이 통하게 씁니다.

한 노트에 한 주제"주소 묶음" 노트에는 주소 묶음만.
첫 줄에 한 문장 정의예: "주소 묶음은 타겟 건물을 가리키는 정규화된 도로명·지번 목록이다."
근거를 붙인다코드 위치와 커밋. 예: pipeline/providers/kakao.py:122-134 (main e1e3c70)
용어는 링크로[[주소 묶음]], [[장소 풀]]. 그래프에서 관계가 보이고, 일부 플러그인은 링크된 노트도 함께 읽는다.
맞다/틀리다를 분명히오해하기 쉬운 점은 "오해: … / 실제: …"로.
머리말(frontmatter)갱신 날짜와 근거 커밋을 둔다.

# 주소 묶음

주소 묶음은 타겟 건물을 가리키는 정규화된 도로명 목록(R)과 지번 목록(J)이다.

- 들어가는 것: CSV 도로명·지번 + 카카오 주소검색 첫 결과의 공식 도로명·지번 + (필요하면) 네이버 지오코딩 주소
- 쓰는 곳: [[장소 풀]]에서 주소 일치 판정, [[건물 내 점포]] 판단
- 오해: 다른 검색 결과들의 주소 → 실제: 같은 건물의 다른 표기만
- 근거: `pipeline/providers/kakao.py:122-134`

권장
자동 커밋을 켜면 의미 없는 커밋이 쌓입니다. 설명서 수정은 PR로 하고, 개인 메모만 자동 커밋하도록 나누세요.

4보안 · 꼭 지킬 것

API 키가 저장소에 올라가지 않게LLM 플러그인은 API 키를 .obsidian/plugins/<플러그인>/data.json에 저장합니다. 볼트가 저장소라면 .obsidian/을 .gitignore에 넣지 않는 한 키가 GitHub에 올라갑니다. 지금 .gitignore에는 .obsidian/이 없습니다.
콜리스트 CSV를 볼트에 두지 않기지금 .gitignore는 work/, results/, .env만 막고 *.csv는 막지 않습니다. 고객 데이터가 담긴 CSV를 볼트(=저장소) 안에 두면 커밋될 수 있습니다.
LLM에 보내는 내용플러그인은 질문할 때 관련 노트 조각을 외부 LLM 서비스로 보냅니다. 설명서에는 실제 전화번호나 고객 정보를 적지 않습니다. 지금 설명서에 있는 번호는 가짜 테스트 데이터입니다.
# .gitignore 에 추가
.obsidian/
*.csv

5LLM 플러그인 설정

대표적인 두 가지입니다. 하나만 고르면 됩니다.

플러그인특징
Copilot for Obsidian채팅 창에서 볼트 전체를 근거로 묻는 모드(Vault QA)가 있음. Claude·OpenAI·로컬 모델(Ollama) 등 선택
Smart Connections노트끼리 관련도를 보여 주고, 노트를 근거로 채팅

설정 순서 (공통)

  1. 1설치설정 → 커뮤니티 플러그인 → 제한 모드 끄기 → 찾아보기 → 플러그인 검색 → 설치 → 켜기
  2. 2채팅 모델플러그인 설정에서 API 키 입력 (예: Anthropic 키 → Claude 모델 선택)
  3. 3임베딩(색인) 모델볼트 전체를 근거로 답하려면 노트를 미리 색인해야 합니다. Anthropic은 임베딩 API를 제공하지 않으므로, 채팅을 Claude로 하더라도 색인은 다른 제공자(OpenAI 등)나 로컬 모델로 설정해야 할 수 있습니다.
  4. 4색인 제외 폴더pipeline/, legacy/, tests/(코드까지 묻지 않을 때), 중복 설명서 한쪽
  5. 5색인 실행 → 질문채팅 창에서 볼트 질문 모드로 묻습니다.

6잘 묻는 법

플러그인 설정의 기본 지시(시스템 프롬프트)에 이런 내용을 넣어 두면 답이 안정됩니다.

너는 이 볼트의 설명서를 근거로만 답한다.
답마다 근거 노트 이름과, 노트에 적힌 코드 위치를 함께 적는다.
노트에 없는 내용은 "설명서에 없음"이라고 말하고 추측하지 않는다.
용어는 [[00_목차]]와 용어 노트의 정의를 따른다.

질문 예

  • "건물 내 점포는 어떤 기준으로 정해? 근거 노트와 코드 줄도 알려 줘."
  • "번호만 대상인 건물에서 KB부동산을 조회해? 집품은?"
  • "중개업소 8곳 한도에 건물 안 중개업소가 들어가?"

7유지 관리

  • 코드가 진실, 노트는 요약. 노트와 코드가 다르면 코드를 기준으로 노트를 고칩니다.
  • 코드를 고치는 PR에서 관련 AI용 md도 같이 고치고, 노트 머리말의 근거커밋을 갱신합니다.
  • 대화에서 새로 알게 된 내용(예: 아래 "주소 묶음과 CSV 주소")은 질문/ 노트로 옮겨 둡니다.

부록 · 주소 묶음과 CSV 주소

질문: "주소 묶음의 도로명·지번은 이미 콜리스트 CSV에 있지 않나?"

  • 맞습니다. CSV의 도로명·지번이 주소 묶음의 출발점이고, 그대로 들어갑니다.
  • 카카오 주소검색은 여기에 CSV에 없는 표기만 더합니다. 정규화한 뒤 CSV와 같으면 아무것도 늘지 않습니다.

  • 카카오 주소검색이 주소 묶음에 보태는 경우는 두 가지입니다. ① CSV에 도로명이나 지번이 비어 있을 때 채움 ② 같은 건물의 다른 지번·도로명을 알려 줄 때.
  • 카카오 주소검색은 주소 묶음 말고도 좌표와 공식 건물명을 얻는 데 쓰이므로, 주소 묶음 때문만으로 부르는 것은 아닙니다.
  • 실제 데이터에서 ①②가 얼마나 자주 생기는지는 아직 모릅니다. 실제 실행 뒤 work/jobs/<작업>/data/<구_동>/A.json의 R·J 개수를 세면 확인할 수 있습니다.
