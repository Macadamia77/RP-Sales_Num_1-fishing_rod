# 세션 마무리 (최신화)

오늘 대화에서 바뀐 것을 저장소 문서에 반영한다. 코드는 고치지 않는다.

## 순서

1. **변경 확인**
   - `git status --short`, `git log --oneline -5`, `git fetch origin` 후 `git log --oneline HEAD..origin/main`
   - 이번 세션에 실행한 작업(작업 ID, 결과 폴더, 건수)을 대화에서 모은다. `.last_job.json`, `결과물/<작업ID>/core/*/summary.json`으로 확인한다.
   - 확인되지 않은 숫자는 적지 않는다.

2. **STATE.md** (매번)
   - 「마지막 갱신」 날짜
   - 1절 코드 기준: main 커밋, 미병합 브랜치, 시험 결과(돌렸으면)
   - 3절 최근 실행: 새 실행을 표에 한 줄 추가
   - 4절 커밋 안 한 변경: `git status` 기준으로 다시 씀
   - 5절 열린 결정: 끝난 것은 지우고 새로 생긴 것을 추가

3. **CLAUDE.md** (규칙이나 실행 방법이 바뀌었을 때만)
   - 오래 유지되는 규칙만 적는다. 그날의 진행 상황은 STATE.md에 쓴다.

4. **저장소 문서** (코드나 사용법이 바뀌었을 때만)
   - 코드 구조: `docs/코드구조_설명서_AI용.md`와 `.html`을 같이 고친다.
   - 사용법이 바뀌었으면 `README.md`
   - 고친 곳에 날짜(예: `2026-10-08`)를 남긴다.
   - `설명서/` 폴더는 git에서 제외됐고 사용자가 저장소 밖에서 관리한다. 고치지 말고, 반영할 내용(로직 이해가 바뀐 점, 실행 결과)을 보고에 따로 정리해 준다.

5. **보고**
   - 고친 파일 목록과 각 한 줄 요약
   - 커밋은 사용자가 요청할 때만 한다. 요청하면 `.env`, `결과물/`, `work/`가 커밋에 들어가지 않는지 확인한다.

## 지킬 것

- `.env`의 키 값을 읽어서 출력하거나 문서에 쓰지 않는다.
- `pipeline/` 코드를 고치면 작업 ID가 바뀐다는 점을 문서에 반영할 때 틀리지 않게 쓴다.
